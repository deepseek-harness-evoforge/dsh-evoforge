## 当前唯一外部阻塞

仓库、当前 DSH home 与当前进程环境均没有可用渠道或模型凭据；没有发现
`DSH_TELEGRAM_BOT_TOKEN`、`DSH_FEISHU_APP_ID`、`DSH_FEISHU_APP_SECRET` 或 provider credential。
真实验收还需要部署者在秘密环境中提供：

- Telegram Bot token，以及一个获准测试的 exact private `chat_id` 与 `user_id`；
- 飞书 App ID/secret，以及获准测试的 exact `chat_id`（或私聊 conversation id）与发送者 `open_id`；
- 一个可同时供 DSH 与 Hermes 使用的同模型 route、预算和 provider credential，用于编码/长任务 paired epoch。

秘密不得写入仓库、benchmark result、聊天正文或模型可见配置。部署者应写入 DSH credential/进程秘密
环境，只需通知“已 provision”；不要在对话里粘贴 token 或 secret。平台身份与 Workspace route 仍须由
部署配置静态给出，模型不能选择或扩大。

## 已验证但不能替代真实凭据的项目

- fake/loopback 平台 API、真实 DSH Host/Agent Loop 和官方飞书 SDK 可以证明协议与生命周期实现；
- deterministic paired epoch 可以证明控制面差异或平局；
- 浏览器、tarball 与 clean-profile 验收可以证明插件产品形态。

它们都不能制造真实第三方账号事实、真实移动端点击、真实服务端消息 id 或同 provider token/成本数据。
因此在外部输入到位前，v0.1 Goal 保持未完成；不得把自动化通过改写成真实渠道通过。
