## 当前外部输入缺口

飞书 App 凭据已通过一次性秘密输入完成身份请求和官方 WebSocket 握手，未写入仓库、命令行或日志。
完成本轮飞书真实消息闭环不再要求部署者手工查平台 ID；只需触发：

- 在 DSH Web 侧栏点击“连接飞书”→“生成一次性短语”（或用 `/feishu-pair start` 备用命令），并在两分钟窗口内向目标机器人发送显示的一次性短语；
- 一个可同时供 DSH 与 Hermes 使用的同模型 route、预算和 provider credential，用于编码/长任务 paired epoch。

本轮按项目所有者要求不验证 Telegram；其真实 Bot 证据保持 pending，但不会在本轮请求 token 或身份。

秘密不得写入仓库、benchmark result、聊天正文或模型可见配置。部署者应写入 DSH credential/进程秘密
环境，只需通知“已 provision”；不要在对话里粘贴 token 或 secret。平台身份与 Workspace route 仍须由
部署配置静态给出，模型不能选择或扩大。

## 已验证但不能替代 exact route 消息的项目

- fake/loopback 平台 API 与真实 DSH Host/Agent Loop 可以证明 Router、Session、Command、Approval 和
  生命周期实现；真实飞书凭据握手另证明 App 身份与长连接可达；
- deterministic paired epoch 可以证明控制面差异或平局；
- 浏览器、tarball 与 clean-profile 验收可以证明插件产品形态。

它们仍不能制造 exact 平台身份、真实移动端点击、真实服务端消息 id 或同 provider token/成本数据。
因此在 exact 飞书路由输入到位前，v0.1 Goal 保持未完成；不得把握手通过改写成真实消息闭环通过。
