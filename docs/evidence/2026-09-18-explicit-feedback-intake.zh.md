# 明确回答反馈接入：预先固定的生产验收

## 发送前固定的范围

本记录在执行下列真实 Provider 任务前创建。输入是虚构但可复现的工作材料，不是客户生产数据。
目标是验证普通 Web 使用及新反馈入口，不把受控回归、一次草稿或重复测试说成学会。
以 `db7437a` 为开发起点；当前生产预算继续为识别4、草稿2、字面对照24，语义模式保持关闭。
明确反馈仅对本次新建的原生会话配置，共享该工作区现有草稿预算，不新建工作区或增加额度。

固定顺序 R1→R2→R3，每条只发送一次；不根据结果换题。只对首个已证实的实质错误提交一条具体负反馈；
其余结果如实记录。如果全部完成，不人为制造反馈或把偏好变化冒充错误。
反馈进入后不读取新生成的封存题目，不改题、不重试来选择有利结果。

7有效评分，5满意、2不满意；评分参与率7/9≈77.8%，满意率5/7≈71.4%。

可使用等价表达和合理舍入，不要求特定标题或逐字匹配。

## R3 退款并发审查

输入：同目录 `退款实现.ts`。
请求：只读该文件，判断能否保证累计退款不超过实付；若不能，给出一个具体并发执行顺序和数值反例，说明最小修复方向。

固定验收：不能保证；两个不同requestId并发读取相同旧余额可各自过检查并外部退款，例如实付10000、已退0，

## 实现及边界

新增可选 `explicitFeedbackSessionIds`，只读取明确授权的原生会话带说明负反馈；与聊天纠正共享原有草稿预算。
它直接引用 native feedback 的版本和持久化事件，不伪造聊天分类结果、不增加识别调用，也不新增聊天轮次。
来源模块统一服务起草和对照检查，逐阶段重核当前反馈/会话前缀，编辑或撤回不得继续生成新结果。
同一回答跨来源、编辑和跨日去重；原生评测 Session 排除在输入来源之外。
普通会话的模型提示、工具与 Skill catalog 未新增贡献；两个后台模型角色沿用原有静态提示。
旧记录保持原样，新增来源元数据由当前读取器兼容；停用方式是撤回来源配置，不承诺旧二进制能够降级读取新记录。
无自动 Skill 启用，也无普通草稿直接发布/回滚入口。
