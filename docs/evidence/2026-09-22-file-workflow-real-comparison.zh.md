## 固定执行与验收条件

- 原 DSH `0.1.6-alpha.1 / 0d1f50007f9bca3f52b06e1c3074fa14d5fb0720`，不修改核心。
  同一生产 Host、同一来源 provider/model `gpt/gpt-5.6-sol`、同一 cwd；不修改用户 Session、凭据或权限。
- h1/r1 先 baseline，h2/r2 先 draft；每题两份全新原生 Session。双方同样的官方文件/Skill/展示工具和路径限制。
  只有 draft 可按需加载该 Skill。首请求仅规范化精确的分支目录和已验证的新增 Skill 目录项，其他组成须一致。
- 每分支最多12次请求、4000输出token/次、600秒总时限；整组保守预留96槽。只有一次提出者请求，没有模型裁判。
  预留不是实际调用或收费次数；实际已知token、工具错误和耗时分别记录，费用未知。
- Agent 必须真正读完输入、写结果 JSON、完整回读并原生 present；不得改输入、访问其他路径、用命令/网络/外发或提权。
  完成度和交付完整性与事实正确性分开；允许恢复普通工具错误，但任何越界使交付检查失败。
- 固定 JSON 类型和值验收忽略空白和对象键顺序，拒绝缺项、额外字段、错误类型或错误事实，不按自然语言逐字匹配。
- 四组均可比、草稿四题均通过、至少一个 holdout 改善、两个 holdout 实际加载、两个 retention 双方均通过且零退化，
  才能进入人工确认的未来会话启用。两边均通过就是没有观察到改善，不为了得到成功换题、改答案、重评分或挑样本。
- 沿用 Generation 的原子选择、当前会话固定和精确回滚；测试失败不自动启用。原生历史及失败文件保留，冷恢复不重发。
