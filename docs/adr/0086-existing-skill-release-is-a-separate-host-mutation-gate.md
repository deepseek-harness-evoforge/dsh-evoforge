# Existing-Skill release is a separate Host mutation gate

Status: accepted — 2026-08-21

An improvement to an installed Skill must not reuse the capability-absent `ReviewInbox`, Shadow report, or missing-Skill lineage. `ExistingSkillRelease` is the only Host module allowed to turn one exact existing-Skill Candidate plus its unique qualified Admission, improved Holdout, and retained Retention into an inactive content-addressed Generation. The Generation carries a dedicated lineage binding the parent baseline archive/tree, Candidate archive/tree, protected evidence, Admission, Envelope, Holdout and Retention identities and both Case Pack hashes. Evaluation owners retain `releaseAuthority: none`; the default path requires an explicit durable human approve, activation is a separate future-Session promote, and rejection is terminal. [ADR-0097](0097-existing-skill-automatic-promotion-is-workspace-scoped-and-fail-closed.md) later permits only a Workspace-authorized, exact append-only, effect-clear and non-regressing instruction Candidate to use the same inactive-publication and future-Session mutation owner automatically; it does not restore static Skill targets. The official DSH scoped Skill Registry selects the Generation provider only inside Sessions pinned to that Generation, so current Sessions never drift; explicit rollback changes only future Session selection. Complete sealed bundles, including inherited binary files, remain byte-identical. We reject synthetic Shadow reviews, evaluator self-promotion, text-only repackaging of installed Skills, current-Session mutation, Git branches as Candidate storage, and any Control or Web path that writes the Generation pointer directly.
