# Internal Candidates replace runtime Skill acquisition

EvoForge Self-Discovery accepts only attributable DSH-owned experience that has become a Skill Opportunity, then authors a quarantined Candidate through one internal `SkillCandidateRepository` seam. We deleted the mixed trusted-local/Agent-Skills/research Candidate model, its old Storage Domain variants and compatibility readers rather than translating them, because preserving those shapes would keep runtime capability acquisition inside the product and make provenance, evaluation authority and Web state ambiguous; design-time ecosystem research remains evidence only and has no runtime interface. Unlike bounded observation queues, content-addressed Candidates are not silently evicted by record count before an explicit governance decision.
