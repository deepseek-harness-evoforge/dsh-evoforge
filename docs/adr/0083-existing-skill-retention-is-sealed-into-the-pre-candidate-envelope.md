# Existing-Skill Retention is sealed into the pre-Candidate Envelope

Status: accepted — 2026-08-21

When a fifth independent existing-Skill correction Goal exists, the Candidate-blind governance module must author Holdout and Retention in separate paid calls before the Candidate proposer runs, giving each call only its exact protected Goal and the sealed baseline. The installed v3 Evaluation Envelope content-addresses both calibrated assembled Case Packs, and the Candidate continues to bind that one exact Envelope id; four-Goal and legacy v2 Envelopes remain readable but contain no Retention authority. We reject post-Candidate Retention case selection and a combined Holdout/Retention author prompt because either weakens sample independence or allows one call to observe both protected roles; any unobserved paid role becomes durable `uncertain` and cannot be retried automatically.
