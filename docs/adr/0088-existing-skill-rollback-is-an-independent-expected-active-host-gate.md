# Existing-Skill rollback is an independent expected-active Host gate

Status: accepted — 2026-08-21

An existing-Skill Canary result is evidence, not authority. The evaluator therefore keeps no reference to `rollbackGeneration`, while a separate `ExistingSkillFutureSessionRollback` Host owner accepts only an explicit human request bound to one exact Canary id. On every request it requires one configured policy, zero durable scan warnings, one unique terminal result for the current Workspace and active Generation, the exact `candidate-regressed-baseline-recovers` classification, four assembled zero-proposer trials, stable composition/input/pointer evidence, and valid sealed Holdout, Retention, baseline, and Candidate hashes. It also re-runs the authoritative `ExistingSkillRelease.eligibility()` and requires the approved Candidate, Admission, Holdout, Retention, and Generation identities to match the Canary. It independently resolves the active Generation's parent, then passes the observed active id to the Generation Store's serialized `rollbackGeneration` compare-and-set. A concurrent pointer change fails instead of rolling back a newer Generation. The action changes only future Session selection; already pinned Sessions remain fixed. Control, generated Remote, and Web call this owner through the distinct `rollbackExistingSkill` action so missing-Skill and existing-Skill Canary authority cannot be confused.
