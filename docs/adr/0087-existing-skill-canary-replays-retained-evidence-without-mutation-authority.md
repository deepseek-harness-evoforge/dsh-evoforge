# Existing-Skill Canary replays retained evidence without mutation authority

Status: accepted — 2026-08-21

A failed Delivery Outcome attributed only to an active Generation is a suspicion trigger, not proof that one Skill caused the failure. The existing-Skill Canary therefore runs only when the active Generation is exactly one approved `ExistingSkillRelease`, revalidates that release and its dedicated lineage, and re-materializes the original installed baseline, the released whole-Skill Candidate, and the pre-Candidate sealed Retention Case Pack through the authoritative Retention owner. It performs a zero-proposer `skill-tree` paired replay under native DSH Jobs. A Candidate that still passes is kept; a Candidate failure becomes `rollback-eligible` only when the exact baseline now passes; both failing is `review`, not rollback. Any pointer change, identity drift, integrity failure, non-assembled execution, calibration/composition mismatch, or unobserved paid result fails closed. The Canary persists content-addressed evidence with `releaseAuthority: none` and receives no Generation pointer writer. A later independent Host gate must revalidate any rollback action.
